The Event Loop

JavaScript runs on one thread. The event loop decides what runs next from three places: the call stack, the microtask queue (Promise.then), and the macrotask queue (setTimeout). Step through the canonical puzzle and watch the output order 1, 4, 3, 2 assemble itself — microtasks always drain before the next macrotask.

    The trap: a setTimeout(fn, 0) feels instant, but 0 is only a
    minimum delay — the callback still waits in the macrotask queue for a free loop tick, and every
    pending microtask jumps ahead of it. That's why 3 (a Promise.then) prints
    before 2 (a setTimeout) even though setTimeout was written first.
